### 3.1 Минимальная настройка операционной системы Debian для удобства работы в ней

#### 3.1.1 Проверка, какая оболочка используется на удалённой машине и установка на zsh

Используя команду:
```
echo $SHELL
```
Далее устанавливаем Zsh на сервере используя команды: 
```
sudo apt update
sudo apt install -y zsh
```

Далее делаем Zsh оболочкой по умолчанию: После установки выполняем:
```
chsh -s $(which zsh)
```
Это изменит оболочку для пользователя на Zsh.

Теперь скопируем настройки Zsh с MacBook на сервер:
```
scp -P 1022 ~/.zshrc user@localhost:~/
scp -P 1022 -r ~/.oh-my-zsh user@localhost:~/
```

На удалённой машине установите утилиты, которые вы используете на хосте.
```
apt update
apt install -y htop (и другие утилиты)
```
#### 3.1.2 Установка SSH-сервер на виртуальную машину для работы через встроеный терминал Mac OS
- Войдем в виртуальную машину и установим SSH-сервер используя команды:

```
su
apt update
apt install -y openssh-server
```

Запустим используя правильную команду QEMU: Убедимся, что мы добавили перенаправление порта SSH (22) на хостовой машине (1022):
```
qemu-system-x86_64 -hda debian.qcow2 -m 2G -smp 2 \
-device e1000,netdev=net0 -netdev user,id=net0,hostfwd=tcp::1022-:22
```

Далее для подключения из терминала выполним команду:
```
ssh user@localhost -p 1022
```

### 7. Настройка виртуальных хостов для Apache

- **Конфигурация виртуального хоста для PhpMyAdmin:**

    ```bash
    nano /etc/apache2/sites-available/01-phpmyadmin.conf
    ```

    ```apache
    <VirtualHost *:80>
        ServerAdmin webmaster@localhost
        DocumentRoot "/var/www/phpmyadmin"
        ServerName phpmyadmin.localhost
        ServerAlias www.phpmyadmin.localhost
        ErrorLog "/var/log/apache2/phpmyadmin.localhost-error.log"
        CustomLog "/var/log/apache2/phpmyadmin.localhost-access.log" common
    </VirtualHost>
    ```

# Ответ на ключевые вопросы 

### 1. Каким образом можно скачать файл в консоли при помощи утилиты `wget`?
Утилита wget предназначена для загрузки файлов из интернета через командную строку. Чтобы скачать файл, необходимо указать его URL в команде. Например, для загрузки архива PhpMyAdmin можно использовать следующую команду:
```zsh
wget https://files.phpmyadmin.net/phpMyAdmin/5.2.2/phpMyAdmin-5.2.2-all-languages.zip
```
Эта команда скачает файл по указанному URL в текущую рабочую директорию. Кроме того, wget поддерживает различные опции, позволяющие, например, возобновлять прерванные загрузки, ограничивать скорость или работать через прокси-серверы.

### 2.Зачем необходимо создавать для каждого сайта свою базу и своего пользователя?
Создание отдельной базы данных и пользователя для каждого сайта является хорошей практикой с точки зрения безопасности и администрирования. Это позволяет изолировать данные между сайтами, что существенно снижает риск: если один сайт будет скомпрометирован, злоумышленник получит доступ только к данным этого конкретного сайта, а не ко всей базе данных на сервере. Кроме того, раздельное управление пользователями упрощает настройку прав доступа и позволяет применять индивидуальные политики безопасности для каждого сайта, что снижает вероятность ошибок при управлении доступом.

### 3. Как поменять доступ к системе управления БД на порт 1234?
Для изменения порта, на котором работает СУБД (например, MariaDB), необходимо отредактировать её конфигурационный файл. Обычно это файл /etc/mysql/mariadb.conf.d/50-server.cnf или аналогичный. Находим строку, содержащую параметр port (например, port = 3306), и изменяем её на:
```
port = 1234
```
После внесения изменений сохраняем файл и перезапускаем MariaDB командой:
```
systemctl restart mariadb
```
Таким образом, СУБД начнёт принимать подключения на новом порту 1234.

### 4. Какие преимущества, с вашей точки зрения, даёт виртуализация?
Виртуализация предоставляет ряд значительных преимуществ:

- Изоляция окружений: Каждая виртуальная машина работает в собственном изолированном пространстве, что повышает безопасность и позволяет тестировать новые настройки или приложения без риска для основной системы.
- Эффективное использование ресурсов: Несколько виртуальных машин могут работать на одном физическом сервере, оптимально распределяя ресурсы и снижая затраты на оборудование.
- Масштабируемость и гибкость: Виртуальные машины легко создавать, копировать, переносить и резервировать, что упрощает администрирование и масштабирование инфраструктуры.
- Экономия энергии и затрат: За счёт консолидации серверов снижается потребление электроэнергии и затраты на охлаждение, а также уменьшается физическое пространство, необходимое для размещения оборудования.

### 5. Для чего необходимо устанавливать время / временную зону на сервере?
Корректная настройка времени и временной зоны является критически важной для стабильной работы сервера по причинам:

- Точность логов: Правильное время позволяет вести корректные записи в логах, что важно для диагностики и аудита.
- Синхронизация задач: Планировщики задач (например, cron) полагаются на корректное время для запуска запланированных заданий.
- Безопасность и аутентификация: Многие сервисы и протоколы зависят от временных меток (например, сертификаты, токены доступа), поэтому синхронизация времени помогает избежать ошибок аутентификации и проблем с безопасностью.
- Корректное отображение данных: Приложения, зависящие от временных меток, будут работать корректно, если временная зона настроена правильно.

### 6. Сколько места занимает установленная вами ОС (виртуальный диск) на хостовой машине?
В моей работе виртуальный диск был создан с размером 8 ГБ. Однако благодаря использованию формата qcow2 фактическое занимаемое место на диске может быть значительно меньше, так как qcow2 поддерживает динамическое выделение пространства. То есть, если на виртуальной машине используется меньше данных, реальное занятие места может составлять лишь несколько гигабайт, несмотря на выделенный объем в 8 ГБ.

### 7. Какие есть рекомендации по разбиению диска для серверов? Почему рекомендуется так разбивать диск?
Для серверов рекомендуется разделять диск на несколько логических разделов, что позволяет изолировать данные и повысить безопасность. Наиболее распространённое разбиение включает следующие разделы:

- `/` (корневая файловая система) – для системных файлов и программ.
- `/home` – для пользовательских данных, что позволяет сохранить их в случае переустановки ОС.
- `/var` – для логов, баз данных и динамически изменяемых данных; этот раздел часто требует большего объёма и может быть настроен отдельно для обеспечения стабильности системы.
- `/tmp` – для временных файлов, что помогает избежать переполнения корневой файловой системы.

Такое разбиение рекомендуется, поскольку:
- Оно повышает безопасность: сбой или переполнение одного раздела (например, /var) не затрагивает другие.
- Улучшает управление резервным копированием: можно настроить отдельное резервное копирование для критически важных разделов.
- Позволяет оптимизировать производительность, так как для каждого раздела можно задать отдельные параметры (например, размер, файловая система, политики монтирования).
